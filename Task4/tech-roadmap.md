# Технологическая дорожная карта

| Зона | Что включить | Обоснование |
| --- | --- | --- |
| Adopt | MDM Customer Hub | Необходим для корпоративного ID и Golden Customer, критичен уже в первые 3 месяца |
| Adopt | PostgreSQL DWH | Нужен для единой управленческой и регуляторной отчётности, подходит для согласованных структурированных данных |
| Adopt | Apache Airflow| Используется для оркестрации batch ETL/ELT и управляемого повторного запуска |
| Adopt | Data Quality framework | Критичен для сопоставления, сверки, проверки ключей и финансовых значений |
| Adopt | DataHub | Обязателен для владельцев, каталога и lineage |
| Adopt | Integration Layer | Заменяет неуправляемые RB point-to-point интеграции |
| Trial → Adopt | Kafka / CDC | Начинать с критичных потоков, после пилота использовать для доставки оперативной дельты |
| Trial → Adopt | S3 + Apache Iceberg | Сначала мигрировать ограниченный исторический домен, затем расширять Lakehouse |
| Trial → Adopt | Trino | Вводить вместе с Lakehouse после проверки профиля запросов и эксплуатации |
| Trial | Доменные Data Products | Пилотировать на Customer 360 и Accounts & Payments перед масштабированием на все домены |
| Assess | Полный Data Mesh | Использовать принципы владения и data-продуктов, но не проводить организационную трансформацию всей компании в рамках 12-месячной миграции |
| Hold | Новые point-to-point интеграции | Увеличивают связность и противоречат целевой Integration Layer |
| Hold | Прямая аналитика из OLTP | Нарушает требование отделить аналитическую нагрузку от банковских операционных систем |
| Hold | Использование DWH как мастер-системы | DWH является аналитическим потребителем и не должен управлять операционными сущностями |
| Hold | Неуправляемый Data Lake без Iceberg/DataHub | Создаёт риск Data Swamp: нет схемы, метаданных, качества и владельцев |
